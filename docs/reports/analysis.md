# 实验数据分析报告(Phase 7 深度分析)

> 2026-08-13。全部计算基于 artifacts 原始数据(analyze_experiments.py 可复现),
> 无推算。

## 1. 容量:理论-实测 0.0000% 偏差(完美闭环)

| ratio | 实测 Tf | 公式 Tf | 偏差 | 增益 |
| --- | ---: | ---: | ---: | ---: |
| 0.25 | 782432 | 782432 | +0.0000% | 3.820x |
| 0.50 | 397360 | 397360 | +0.0000% | 1.940x |
| 0.75 | 269002 | 269002 | +0.0000% | 1.313x |
| 1.00 | 204824 | 204824 | +0.0000% | 1.000x |

**机理**:KV byte budget 守恒 T0(F+C) = Tf·F + Tc·C 在双池分配中精确成立。
comp 池占用总预算仅 3.00%(Tc×C / T0×(F+C) = 1.57M/52.4M,ratio 0.5),
因此容量增益逼近理论极限 1/(F/(F+C))。这是"显存重新分配"叙事的硬证据:
省下的 compact head 显存几乎 1:1 转化为 full 池容量。

## 2. 单请求:开销是固定启动成本,不随长度增长(核心洞察)

| len | FullKV | DuoKV | Δ% | 绝对差 |
| --- | ---: | ---: | ---: | ---: |
| 4K | 1.041s | 1.375s | +32.1% | **+0.334s** |
| 8K | 1.377s | 1.712s | +24.3% | **+0.335s** |
| 16K | 2.121s | 2.447s | +15.4% | **+0.326s** |

**绝对差恒定 ≈ 0.33s(4K/8K/16K 一致)**,百分比下降只是基数变大。
→ 开销不是"每 token 双路计算"(计算量本就相同,comp 只是窗口小),而是
**固定启动成本**:full/comp 分组 Q gather(两次 contiguous)、双路
decode/extend kernel launch、restore_indices 还原、window metadata 构造。
→ 推论:序列越长,相对开销越小;batch 越大,固定成本被更多请求摊薄
(Exp D memory-bound 持平正是此机理)。

## 3. 并发:prefill 波次是瓶颈,非 KV 池

8K × bs 并发(16 decode):
- median 时延 ≈ 0.65s/req 线性斜率,双方一致 → max_prefill_tokens=16384
  决定的 prefill 波次串行代价主导
- bs=48(393K tokens,超双方池):DuoKV 31.02s vs FullKV 31.56s(-1.7%)
- decode-heavy(4K×64×128=256K,超 FullKV 池):双方持平(±1%)
  → eager 下池满排队被流水线摊平,容量红利不转化为端到端时延,而是
  表现为 max_total_tokens(准入上限)与 KV 占用:
  **同 16 并发下 token usage FullKV 0.31 vs DuoKV 0.16(减半)**

## 4. Online:memory-light 0.78x / memory-bound 1.00x

- memory-light(512 ctx):固定开销占比高 → 0.78x(与单请求 0.33s 同源)
- memory-bound(8K ctx, 16w):长 prefill 摊薄固定开销 → 持平
- 结论:DuoKV 的开销在短上下文低并发场景最明显,长上下文高并发场景消失

## 5. 质量:无损(方向性略优)

| 测试 | FullKV | DuoKV | Δ |
| --- | --- | --- | --- |
| NIAH 4K(depth×seed=9) | 9/9 | 9/9 | 0 |
| narrativeqa(40) | F1 0.1376 | F1 0.1676 | +21.8% |
| 2wikimqa(40) | F1 0.1217 | F1 0.1254 | +3.0% |

机理:ratio 0.5 时 50% head 为 full(全历史),retrieval 型信息可由 full
heads 承载;sink(128)+ recent(256)覆盖局部性信息。LongBench 两任务 DuoKV
方向性略高,样本量小(40),保守表述为"持平或略高"。

## 6. 总结论与项目定位

1. **容量提升真实且可预测**:理论-实测 0 偏差,3.82x 上限
2. **开销可解释**:0.33s 固定启动成本(非随长度增长),CUDA Graph 开启可
   直接消除(深化方向)
3. **定位**:capacity-oriented serving —— 长上下文/高并发场景收益兑现,
   短上下文低并发场景付固定成本
4. 诚实边界:单请求不加速、eager 下吞吐不提升、容量红利在准入与 KV 占用

## 7. 面试叙事升级

- "绝对差 0.33s 恒定"是比"慢 15-32%"更强的洞察:证明开销是启动成本而非
  计算量增加,并且指明了消除路径(CUDA Graph)
- 理论-实测 0 偏差:预算模型的可预测性(面试可现场推导)
- comp 池 3% 开销占比:解释"为什么增益接近理论极限"
